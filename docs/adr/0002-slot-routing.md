# ADR 0002: slot-based шардирование по `user_id`

## Контекст

Нужно горизонтальное масштабирование без переписывания всех запросов и с возможностью
переключать слоты между шардами.

## Решение

- 1024 слота: `slot = xxhash64(BE64(user_id)) & 1023`.
- `dbrouter.Config` (generation) отображает диапазоны слотов на именованные шарды.
- `user_directory` хранит `user_id`, `email_hash`, `slot`, `shard_id` (глобальная БД).
- `Router.UpdateConfig` атомарно меняет generation, сохраняет соединения/метрики
  для оставшихся шардов и закрывает удалённые.
- `cmd/userdir -action recompute` пересчитывает `shard_id` после смены slot-map;
  `-action verify` проверяет консистентность.
- `cmd/dbverify` сравнивает `COUNT(*)`/`SUM(CRC32(key))` между источником и целевым
  шардом по пользователям или слоту.

## Последствия

- Существующие `int` ID не переписываются; новые ID — Snowflake.
- Переключение слотов не требует изменения кода вызовов.
- Реальные запросы пока не маршрутизируются через `dbrouter`; это следующий этап.
